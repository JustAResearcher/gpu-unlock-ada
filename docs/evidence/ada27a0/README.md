# MSI RTX 4080 Laptop 27a0: one A/B/A cycle

These observations accompany [the hardware report](../../ada-27a0-report.md). A is original stock, B is one successful experimental unlock boot, and A-prime is restored stock. All phases used the same GPU, kernel, driver and hashed compute inputs. Firmware pins and power policies were unchanged. Desktop activity, temperature, clocks and Dynamic Boost were not controlled.

Run `python3 docs/evidence/ada27a0/verify.py` from the source tree. This needs only the Python standard library and no GPU. It checks exhaustive SHA-256 coverage, expected RM rates, seeded checks, all large-GEMM output/error counts, checked tensor modes, matched Strata request hashes and short-soak results, then recomputes every published summary and CSV entry in a temporary directory. Hashes establish byte integrity, not independent hardware attestation.

## Contents and collection

- `transaction-excerpt.txt`: all `gpu_unlock:` lines from the unlocked boot's pre-workload kernel journal, with timestamp/hostname prefixes removed. It records the device's own ROM geometry and successful unlock; no ROM bytes are included.
- `manifest.json`: matched CUDA benchmark binary/source hashes and local build provenance. Hardware module hash identifies the original tested build, not the later wording-only rebuild. Private absolute paths and GPU UUID are removed. Local research commit IDs are provenance labels, not public branch ancestors.
- Each phase: three `mma-*.txt` rounds (`mma_bench 20000 5`, 15 samples/mode), three `gemm-*.jsonl` rounds (15 samples/shape), three checked tensor rounds (9 samples/mode), six seeded CPU-reference cases, PyTorch observations, SM issue rates and 200 ms telemetry. `power.limit` is legitimately N/A on this laptop.
- `strata/results.jsonl`: ten synthetic benchmark requests per phase, one excluded warmup plus short/4K/17K input groups with three repetitions each. Fixed temperature 0, fixed per-repetition seeds, 256 output tokens, no thinking, zero prompt-cache reuse. Only generated response prose was removed; request hashes, completion flags, usage, timings and speculative acceptance counts are retained. `strata-manifest.json` and `manifest.json` record model/config/engine input identities. These are engine timings, not model-quality validation.
- `soak/`: 300-second BF16 4096-cubed GEMM runs in B and A-prime. Inputs are constant 0.125 and 0.25; each 100-GEMM batch checks the entire output against exactly 128, then records cumulative GEMMs/cells/mismatches. A seeded independent validator ran again afterward. Constant-input checks do not replace the independent seeded cases or establish arbitrary workload correctness.
- `summary.json` and `comparison.csv`: all measured groups, including unchanged or slower controls, with medians, ranges and counts. `summarize.py` is the aggregation script used locally. `matched-audit.json` records the local collection audit; `verify.py` checks the published subset independently.

FP8 is an instruction-throughput probe only. PyTorch numerical checks are sampled for large matrices and use a small reference Attention problem; they do not check every large Attention output. The first Strata collection attempt raced HTTP startup after compute finished. The router was given readiness polling and the complete Strata stage rerun on the same unlock boot. Its failed partial attempt remains in local records and is not represented as another successful run here.

One unlock boot plus a stock recovery and two five-minute soaks do not establish repeated-boot, suspend/resume, D3cold, other-OEM or long-term compatibility. No new Xid/GPU loss was seen in the local full journals; two SBIOS assertions were already present in stock. Full machine journals, private identifiers, filesystem/device UUIDs, signing material, binaries, firmware and ROM images are deliberately not published.
