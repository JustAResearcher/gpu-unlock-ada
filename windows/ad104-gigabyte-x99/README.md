# Экспериментальный порт разблокировки RTX 4070 Ti для Windows — Gigabyte / Huananzhi X99

Ручной порт UEFI-загрузчика для связки **Gigabyte GeForce RTX 4070 Ti (AD104-400 / Subsystem 1458:40e8)** на материнской плате **Huananzhi X99-F8D Plus (Intel C612 / X99, BIOS AMI Aptio IV/V)** под управлением **Windows 11 x64 (NVIDIA Driver 616.92)**.

Проект базируется на наработках [JustAResearcher/gpu-unlock-ada](https://github.com/JustAResearcher/gpu-unlock-ada) и [impacifist/Windows-GPU-UNLOCK](https://github.com/impacifist/Windows-GPU-UNLOCK). Загрузчик отрабатывает в фазе UEFI до инициализации видеодрайвера Windows и позволяет запускать видеокарту без ошибки «Код 43» с полным доступом к тензорным ядрам.

## Сравнение производительности: Сток vs UEFI-Анлок (cuBLAS GEMM)

Тестирование проводилось на физическом оборудовании в среде Windows 11 x64 с официальным драйвером NVIDIA 616.92 при помощи PyTorch 2.6 cuBLAS:

| Тест (cuBLAS 4096² GEMM) | СТОК (без анлока) | С НАШИМ UEFI-АНЛОКОМ | Разница / Прирост | Энергопотребление |
|---|---:|---:|:---:|:---:|
| **BF16 Tensor Cores** | **73.19 TFLOP/s** | **143.76 TFLOP/s** | **+96.4% (в 2 РАЗА БЫСТРЕЕ!)** 🔥 | **284.9 Вт** (TDP 100%) |
| **FP16 Tensor Cores** | **73.58 TFLOP/s** | **140.10 TFLOP/s** | **+90.4% прирост** | **278.0 Вт** |
| **FP32 CUDA Cores** | **26.82 TFLOP/s** | **27.29 TFLOP/s** | **Паритет** (CUDA-ядра не режутся) | **283.9 Вт** |

> [!NOTE]
> **Физика процесса и энергопотребление**:
> - В тесте **FP32 (CUDA-ядра)** видеокарта и в стоке, и с анлоком упирается в максимальный аппаратный лимит платы (**~284 Вт**) и выдаёт одинаковые паспортные **~27–28 TFLOP/s**, так как стандартные векторные шейдеры NVIDIA не лочит.
> - На **тензорных ядрах (FP16/BF16)** в стоковом режиме драйвер искусственно сдерживает скорость планировщика: видеокарта намертво упирается в потолок **80.6–80.8 TFLOPS** даже при разгоне ядра до 2775 МГц.
> - Наш UEFI-загрузчик снимает эту блокировку прошивки: тензорные ядра выходят на полную кремниевую скорость **142+ TFLOP/s** при потреблении **276–284 Вт**, полностью насыщая аппаратный лимит питания платы.

## Особенности связки и параметры железа

- **Видеокарта**: Gigabyte GeForce RTX 4070 Ti EAGLE/GAMING (AD104-400, PCI ID `10de:2782`, Subsystem `1458:40e8`, ревизия A1).
- **VBIOS**: Версия `95.04.3c.c0.d2`.
  - Размер Slot 0 payload: **626 176 байт** (`0x98e00`).
  - SHA-256 чистого VBIOS: `35a6c1ad3225b1266cfacaf6ea014f137f32c54888eb676e230a33a8ac9d19c2`.
  - SHA-256 1 МБ PROM MMIO (`BAR0 + 0x300000`, дополнено 0xFF): `4891c171e39da7839677b115c7acd6df77720a53b23c7d8ad5226d2c6f42ba05`.
- **Материнская плата**: Huananzhi X99-F8D Plus (Dual LGA2011-3, чипсет Intel C612 / X99, UEFI AMI Aptio IV/V).
- **Базовый адрес BAR0**: `0xc6000000ULL` (размер апертуры 16 МБ).
- **Селекторы подсистемы**: На входе `SS0=0x41145131` / `0x60145131`, `SS1=0x4` $\rightarrow$ Фиксация защёлки: `SS0=0x88888888`, `SS1=0x8`.
- **Драйвер**: NVIDIA 616.92 (загрузка чистая, диспетчер устройств рапортует «Устройство работает нормально»).

## Архитектура динамического отрыва GOP-консоли (`x99_release.c`)

В оригинальном upstream-порте для MSI Z490 использовались жёстко захардкоженные адреса хэндлов и статическое дерево USB-устройств. На платах X99 с AMI Aptio BIOS такая схема приводила к зависаниям или ошибкам `0x8000000000000002` (EFI_INVALID_PARAMETER), так как топология хэндлов динамически меняется при каждой инициализации.

В модуле [`x99_release.c`](x99_release.c) реализован универсальный динамический механизм:
1. **Поиск активного драйвера**: Через `OpenProtocolInformation()` на хэндле видеокарты находится реальный агент видеодрайвера GOP (`EFI_OPEN_PROTOCOL_BY_DRIVER`).
2. **Безопасное отключение контроллера**: Вызывается `DisconnectController(pci, nv_agent, NULL)`, что корректно отключает графическую консоль без повреждения шины PCI Express.
3. **Эксклюзивный захват (Mutual Exclusion)**: Вызывается `OpenProtocol(..., EFI_OPEN_PROTOCOL_EXCLUSIVE)`.
4. **Восстановление бит PCI Command**: Если стек UEFI сбросил биты Bus Master, Memory или I/O decode при отключении, модуль считывает исходный регистр конфигурации `0x04` и принудительно восстанавливает их.
5. **Освобождение перед Windows**: После успешной заливки прошивки Falcon/SEC2, инициализации GSP и проверки сброса FLR, вызывается `CloseProtocol()`, позволяя видеодрайверу Windows перехватить управление без перезагрузки системы.

## Сборка бинарника

### Способ 1: Автономный скрипт `build.py` (Рекомендуемый)
Не требует Visual Studio, компилирует через MinGW/w64devkit, автоматически обнуляет таблицу импорта PE и проверяет результат:
```powershell
python build.py

# Сборка и прямая запись на подключенную флешку (например, G:):
python build.py --deploy G:
```

### Способ 2: Скрипты PowerShell
```powershell
# Создайте файл с GUID вашего раздела ESP:
New-Item -ItemType Directory -Force local
Copy-Item boot_profile.example.h local/boot_profile.h
# Пропишите в local/boot_profile.h GUID вашего реального Windows ESP раздела

# Сборка через GNU ld:
.\Build-Experimental.ps1 -UseLd

# Или сборка через MSVC (если установлены C++ Build Tools):
.\Build-Experimental.ps1 -Python python
```

Результат сборки: `build/AD104-EXPERIMENTAL.EFI`.

## Подготовка флешки и запуск

1. Отформатируйте USB-флешку в файловую систему **FAT32**.
2. Скопируйте файлы согласно структуре:
```text
USB_ROOT/
├── EFI/
│   └── BOOT/
│       └── BOOTX64.EFI              <-- Скомпилированный AD104-EXPERIMENTAL.EFI
└── AD104-ASSETS/
    ├── booter_load_ad102.bin        (57 672 байт)
    ├── v67-ad102-610.43.03-four-plm.bin (64 000 байт)
    ├── gsp_ga10x.bin                (84 277 400 байт)
    ├── gsp_boot_ad102.bin           (36 864 байт)
    └── gsp_boot_desc_ad102.bin      (84 байт)
```

*(Файлы прошивок извлекаются из официального архива NVIDIA 610.43.03 с помощью скрипта `tools/porting/extract_assets.py`).*

### Запуск системы:

> [!IMPORTANT]
> **Требуется физический «холодный старт» (Cold Boot)!**  
> Не используйте вход в меню `Boot Override` из настроек BIOS — в этом случае видеокарта уже будет инициализирована прошивкой материнской платы, а защитные проверки загрузчика (`checks.c`) отклонят транзакцию.

**Рекомендуемый порядок запуска:**
1. Отключите **Secure Boot** в настройках BIOS.
2. Во вкладке **`Boot`** выставьте вашу USB-флешку на **1-е место (Boot Option #1)** и сохраните настройки (`F10`).
3. **Полностью обесточьте ПК** (выключите тумблер на блоке питания или выдерните сетевой шнур на 10 секунд, чтобы разрядились конденсаторы и GPU перешёл в чистый аппаратный Cold Reset).
4. Включите ПК кнопкой питания — материнская плата сама, без нажатия клавиш, на холодную запустит загрузчик с флешки.
5. Появится текстовое меню загрузчика. Нажмите клавишу **`U`** (один раз) для применения разблокировки.  
   *(Если нажать `S`, `Esc` или подождать 30 секунд — загрузится обычная Windows без изменений состояния GPU).*
6. Картинка застынет на 2-3 секунды (происходит освобождение GOP, инжекция микрокодов и передача управления `bootmgfw.efi`), после чего начнётся стандартная загрузка Windows 11.
7. Лог выполнения транзакции сохранится на флешке в папке `AD104-UNLOCK/RUNxxxx.TXT`.

*(Альтернатива: если флешка не стоит первым диском, при включении из полностью обесточенного состояния часто нажимайте **`F7`** для быстрого текстового Boot Menu).*

## Утилиты для портирования (`tools/porting/`)

В папке [`tools/porting/`](tools/porting/) собраны вспомогательные инструменты:
* **`dump_vbios.bat`** — создание дампа VBIOS через `nvflashk` в режиме чтения.
* **`parse_vbios_fwsec.py`** — скрипт парсинга структуры VBIOS, поиска смещений FWSEC, расчета точного размера Slot 0 и генерации C-кода для `profile.c`.
* **`extract_assets.py`** — проверка целостности и перенос микрокодов на USB.
* **`benchmark_bf16.py`** — бенчмарк для проверки скорости и энергопотребления под Windows.
